Reviewed: 2026-10-05

The [C1 decision](../decisions/2026-10-05-console-m4-oem-source-intake.md) retains the private OEM

## Keep Designation And Fitment Separate

An exact declared manufacturer/reference string is a source subject, not proof of equivalent
geometry or compatibility. Preserve punctuation, case and leading digits. A similar number, label,
model name or catalog family must not transfer evidence to another SKU or manufacturer.

Keep each source's class, level, basis, custodian, date, document version/location and assertion.
Contradicting evidence remains visible and immutable. Company catalogs and official manufacturer
references do not themselves confirm ArcFort's exact supplied product. A qualifying source-metadata
check is preparation for human review, not a recorded approval or document-content verification.

## Retain The Original Authority

Source intake appends separately from original `oem_references`. Preserve all imported records,
compatibility, technical/media states and publication history. Current SKU identity and full source
hashes prevent silent reuse after drift. Private commands have no application grants yet.

The C1 embedded rehearsal uses four real 15AK identities plus one created synthetic draft, but its
reference strings are explicitly TEST-ONLY. It proves scoped SQL intake and rollback, not real
OEM truth, actual Auth/PostgREST or a completed reviewer interface. Continue through governed
proposals/review and native acceptance before activating the workflow; never publish test evidence.

## Frozen Decisions And Effective Reads

The [C2 decision](../decisions/2026-10-05-console-m4-oem-human-review.md) extends C1 with private
proposals and human decisions. Original `oem_references` remain separate. Stable SKU/slot heads
retain explicit original lineage; corrections append revisions. Exact pending snapshots include
all known contradictions even when the reviewer does not select them. EDIT cannot erase unresolved
conflict by changing a number or omitting evidence. REJECT preserves the preceding current record.

An explicitly reviewed Level B manufacturer source remains `OEM_REFERENCE`; it is not confirmed
ArcFort data. `CONFIRMED` requires a human declaration and a selected qualifying exact Level A
source. These are evidence metadata/declarations, not an automated document-content certification.
Never transfer either status into compatibility or public facts. Publication remains false for all
effective OEM records until the separate release authority exists.

New contradictions or SKU/original/source drift invalidate the current approval and remain visible
as `DATA_CONFLICT`; do not silently resurrect an old original record. Later reviewer revocation
does not erase the historical decision, but does deny current reads, new writes and receipt replay.
Unresolved OEM records block readiness without removing technical, media, SEO or other blockers.
The existing dashboard's technical-conflict metric remains technical; use the separate OEM
readiness fields for OEM conflicts rather than assuming the old dashboard now covers them.

C2 tests freeze five TEST-ONLY reference proposals on the four real 15AK identities plus a created
synthetic draft and verify that company-catalog/reference-only evidence cannot confirm any of them.
All original rows and post-rollback state remain exact. Native services, actual OEM document
verification and the owner workbench are still required; no real reference is confirmed here.

## Application Workbench

The [C3 decision](../decisions/2026-10-05-console-m4-oem-workbench.md) adds the application workbench
without changing the C1/C2 factual gates. The earlier private-only command checkpoint remains
historical: migration 21 prepares authenticated public wrappers, while private implementations and
direct writes stay denied. Its application flag is default-off and does not itself revoke SQL RPCs
after a separately approved native migration. No native database is migrated in C3.

The UI separates imported originals, current approvals, correction proposals, source metadata and
historical decisions. Editing cannot submit/approve an old snapshot. Source creation is not source
selection or approval; approval choices must be in the frozen proposal. Reload clears unsaved edits,
stale-command state and acknowledgement choices. Exact numbering and contradictory evidence remain
visible at all tested widths, with no inferred aliases or compatibility claims.

Counted reads and observed-state/role rechecks fail closed on detectable drift, partial pages or
detached evidence. They are not a transactional snapshot across HTTP calls. Native SQL/Auth/
PostgREST/concurrency and actual document inspection remain necessary. Synthetic browser declarations
and the real-identity TEST-ONLY SQL rehearsal do not confirm any actual OEM reference.

## Disposable OEM Acceptance

The [C4 decision](../decisions/2026-10-05-console-m4-disposable-oem-acceptance.md) prepares an
explicit `--local --oem` extension of the pristine disposable runner. Default entrypoints do not
perform OEM writes. Native form/SDK races require observed PostgreSQL blockers, exact frozen
sources and independently checked ledger/retention; the sequential in-memory rehearsal does not
prove those native services or races. All OEM metadata and declarations remain TEST-ONLY.

An exclusive free bind is insufficient proof that a loopback provider is absent. A current
read-only Auth response demonstrated that difference; its service identity is not established.
No-provider checks now require actual connection refusal before any server/browser/form/command
activity. HTTP errors, policy denial and timeouts do not establish absence. Do not disable a
retained endpoint to satisfy the test. Native acceptance and real OEM document verification remain
separate gates, with no inferred Docker health, compatibility or public approval.
