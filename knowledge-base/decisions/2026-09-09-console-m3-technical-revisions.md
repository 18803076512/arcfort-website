## Decision

Keep current-value pointers and review state outside original `technical_values` rows. A new proposal
is a new value with lineage; pending replacement never erases the current value. Separate factual
verification status from proposed/pending/approved/rejected/superseded review state. A rejected
first revision has no implicit current value. Historical CONFIRMED rows cannot satisfy readiness.

Use immutable source bindings for exact variant UUID, field UUID, scope label, asserted value/unit,
document revision/location and source hash. New sources are separate records; raw catalog snapshots
are not edited. Generic source flags, a family label or matching appearance are insufficient. Keep
the original fifteen pilot references and all holder-side/nozzle-profile scopes distinct.

Commands serialize on working authority, lock current role grants and use actor/command/request
receipts with payload digests. The proposal digest includes the complete candidate, linked sources,
roles and bindings. Submit binds that digest. Approval rechecks it and requires matching exact-item
Level A evidence plus a server-attributed APPROVE event for the same candidate and source list.
Hash functions pin UTC so different session time zones cannot manufacture stale-source errors.

Reviewer EDIT appends an unconfirmed proposal. It cannot be reused as APPROVE, and it carries an
unresolved conflict forward. An ordinary save cannot silently replace a conflicting proposal.
Conflict approval requires qualifying evidence and an explicit resolution reason; reject is an
explicit human disposition and leaves all history intact. Decisions and failed operations are atomic.

The new metadata tables are forced-RLS and read-only to current Console roles; no client/service
write grant or private-command EXECUTE is added. The effective view is security-invoker. Application
read/write integration remains gated work, since the hosted database does not have this migration.

## Alternatives And Consequences

Overwriting the original value destroys provenance. Marking confirmed rows non-current in place
conflicts with existing confirmed-value immutability. Timestamp-only events do not bind the reviewed
value/evidence version. Separate heads and append-only value/evidence rows avoid these failures.

The common authority lock deliberately serializes pilot commands; it is not a proven large-scale
throughput strategy. Measure real multi-connection races and contention before widening the scope.
The private commands alone are not a usable Console workflow or a completed M3 milestone.
