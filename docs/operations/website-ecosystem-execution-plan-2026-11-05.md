## 目标：把网站变成可核实的业务闭环

最终运行链路是：**有来源的公司与产品事实 → 受控产品数据和图片 → 清楚且可抓取的页面 → 可追踪的询价 → 双邮箱交付与人工跟进 → 合格线索、报价和订单反馈 → 改进产品与页面**。

第一道长期产品门槛是 100 个通过严格证据门槛的 SKU，然后按 Goal Mode 的 300、500、1000+ 阶段扩展。SKU 数量是结果，不是放宽技术、适配或图片证据的理由。网站、目录、经销商资料与未来 Console 必须使用同一套受审事实；公开站只能从受控、已批准的发布快照取得产品事实。

## 主要问题的因果顺序

1. **线索交付缺最后一环。** 配置就绪和服务商接受均早于销售邮箱实际收到邮件；买家确认和附件又是两个独立结果。旧受控提交缺时间与日志，无法判定失败、延迟或已被服务商受理。先取得同一参考编号的完整证据，才能计算可靠的询盘转化。
2. **产品覆盖快于证据。** 40 个公开产品有浏览入口，但图片权益、同款识别、关键技术和适配证据未闭环。搜索流量增加后，买家仍可能无法确认型号；把未确认字段写成规格会增加报价与信任风险。
3. **测量链路断开。** 站点可抓取不等于 Google 已收录；历史 GSC 不能决定今天的内容优先级。GA4 客户端事件又不能代替服务商接受、邮箱收件或销售人工认定。
4. **销售操作有手册，缺可观察结果。** 邮箱与 Resend 每工作日至少查看两次、保留 RFQ 编号、人工审核并记录下一步是既有流程；实际执行和响应时间尚无记录。多渠道推广前需要私有台账与负责人。
5. **内部系统不能越过发布门槛。** Console 能帮助收集、复核和追溯证据，但公开资料权威切换必须在真实 15AK 试点、托管验收、不可变发布快照和单独批准后进行。
6. **持续监测测试稳定性。** PR #140 的数据库浏览器作业曾在包装资料选择处单次超时，单作业重跑及合并后的主分支均通过。这不能证明偶发原因已修复；若再现，应记录无买家资料的表单状态、可见选项和源记录状态后定位，不直接放宽超时。

## 分阶段执行与退出门槛

以下时间是**所需资料和账户可用后的建议节奏**，不是对外承诺。若证据未到，保持未核实状态并推进不依赖该证据的工作。

### 阶段 0：保护线索并恢复可观察性（资料齐备后 0–14 天）

1. **旧 RFQ 只读追踪。** 以一次受控尝试的时间窗口、Vercel `rfq_delivery_result`、Resend 状态和双邮箱记录核对同一编号。若记录不可取得，明确保留“结果未知”，不自动重提。下一次真实受控测试必须另获发送授权，并在旧尝试处理边界清楚后，以新唯一编号核对销售邮件、买家确认和销售附件；把各自时间和审核人写入生产证据。
2. **发信凭据与身份。** 在服务商账户确认外露 Resend 凭据已轮换；仅记录确认状态，不保存密钥。确认 Resend 发信域后，评审 Cloudflare 的 `_dmarc.arcfortweld.com` TXT 初始 `p=none`，有受控聚合报告邮箱才加入 `rua`；DNS 写入、观察与回滚须单独批准。以两个 DNS 解析源和一封受控邮件头复核对齐。
3. **恢复原生搜索数据。** 从 `arcfortweld.com` GSC 域名属性导出最近完整 28 天及之前 28 天的属性总量、查询和页面数据，记录搜索类型/筛选；另取 sitemap 状态及“重定向错误”示例 URL、最后抓取和 Google 选定 canonical。按准确 URL 修复，不因为本站 HTTP 200 就关闭 Google 问题。
4. **建立最小销售台账。** 已备好空白 [RFQ 台账模板](../sales/rfq-sales-ledger-template.csv)；实际记录应放在私有邮箱/受控表格中，按 RFQ 编号保存接收、负责人、资格、首次答复、下一步、报价/订单结果；买家身份与附件不得进入 Git 或分析事件。建议运营目标是每工作日至少两次检查，并在一个工作日内给有效询盘首次答复；先记录基线，再决定是否调整服务目标。

**退出门槛：** 旧尝试得到可核对结论或显式保留未知并有对应处理决定；邮件轮换状态有账户证据；DMARC 状态得到独立核验；GSC 有当前可比基线；销售台账有责任人。RFQ“已验证送达”只在新授权测试的双邮箱与附件三项证据完整时成立。

### 阶段 1：四款 15AK 真实产品闭环与测量（资料齐备后 15–45 天）

1. 工厂/产品审阅人按现有工作簿返回 CT0004、CT0005、TH0007、GN0008 的精确 SKU 或变体实物、受控图纸/测量记录、原始图片、来源人、网站使用权、审核人和日期。15 条技术事实逐字段比对；冲突保持 `DATA_CONFLICT`。`AF-MIG-CT-0006` 的 M6×27 mm 通用依据走独立队列，不能混入 15AK 的 25 mm 依据。
2. 逐条转入权威 intake、图片注册表、技术事实与适配关系，运行对应验证、报告、页面预览与人工审核；仅通过发布门槛的事实、同款图片和关系进入公开页面。三款缺照片的草稿继续不索引，直至同款图片通过。
3. 在真实 GA4 数据流和隐私配置核对后配置生产测量 ID；以同意分析的浏览器验证页面、表单开始、`rfq_submit_success` 和 `generate_lead`，检查事件不带买家个人信息。事件只衡量客户端行为；服务商、邮箱与销售资格分别核对。
4. 以当前 GSC 数据选择少数高意图已有分类/产品/经销商页面，做移动、键盘、附件、超时和备用联系路径的真实浏览器复核；只修实际发现的问题。经销商外联先保持小批、人工核对与私有结果记录。

**退出门槛：** 15AK 四款逐 SKU 有可追溯的审查结果，已通过者才计入“严格验证 SKU”；产品页、图片权益、技术和适配状态一致。GA4 Realtime/DebugView、生产事件与销售台账分别有证据。现有 URL、canonical、RFQ 及移动端体验在发布后复核。

### 阶段 2：复制可验证的增长机制（资料齐备后 46–90 天）

1. 用 15AK 的证据与发布流程选择下一批最有供货/买家价值且证据可得的 MIG/MAG、TIG 或等离子产品；先解决 602 的页身份冲突，再考虑相关系列页。每一批只扩一个可审查的产品/页面家族。
2. 每周比较原生 GSC 的商业意图查询、落地页、索引异常与经同意的站内事件；每月与私有合格询盘、报价和订单结果复盘。只有完整基线后才设点击、转化率或线索量的数字增长目标。
3. 评估销售台账是否需要带权限、附件保留和查询能力的正式 CRM/私有存储。若现有私有表格足以承载，不因技术可用性就启用新付费或生产数据库。
4. 评估 Console 的真实 15AK 试点与托管 M4 角色/存储，再设计 M5 冻结预览、QA 和不可变发布快照。公开数据权威从仓库转移只限经审阅的一小批，并需独立的回滚、迁移和批准。
5. 中国与国际市场先形成内容、语言、URL、hreflang/重定向和衡量方案，复用同一已核实 SKU；在取得市场证据和迁移审查前不直接创建 `/zh/`、`/en/` 或机器翻译页。

**退出门槛：** 第二批证据可重现、内容优先级由当前查询和合格询盘支撑、每次发布可回滚；销售和搜索数据能追溯到各自原始系统。Console 公共权威切换仍以单独发布决策为门槛。
